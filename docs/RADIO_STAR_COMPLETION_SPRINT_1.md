## Defects and safeguards

The previous capacity hold remained parked until its original midnight even after an authorised allowance increase. Recovery now rechecks authoritative atomic capacity and resumes the existing job. Tester membership cannot substitute a separate, larger financial ledger. Activation retained all 461 existing usage rows and existing totals.

HPR chunk 8 returned a valid saved response whose last segment was 1193.719970703125–1202.0799560546875 seconds for a verified 1,200-second input. The old two-second tolerance rejected its 2.080-second terminal overrun. Assembly v3 permits at most three seconds **only for the final segment starting within the last fifteen seconds**, clips to the measured input extent and retains `providerEndMs`/precision provenance. Nonterminal, larger and invalid timings still fail. Tests reproduce the observed shape using a saved response and prove zero additional transcription calls. Recovery preserves the original job and all saved chunks.

Incomplete briefs/chapters came from rejected claims, including inline numbered citations treated as unsupported numeric assertions, unsupported paraphrases and one unknown review outcome. Generation now keeps references exclusively in structured citation fields. Feature repair uses the existing generator, independent claim reviewer, checkpoints and shared ledger; regenerates only incomplete outputs; preserves good outputs; rechecks rights and source identity before spending/publication; and stops on unresolved outcomes or rejected claims. It does not strip unsupported numbers or weaken grounding checks. Partial search/topics remain usable throughout.

Confidence filtering had separately discarded 53 HPR speech segments despite strong decoded-text confidence. The repaired filter follows the distinction between a high silence posterior and low text confidence; four local ASR samples exposed the omission. Canonical assembly v4 restores those exact saved segments without new audio requests, retains the prior transcript for audit, and removes exact duplicated prefix phrases only across overlapping chunk boundaries. IDs, measured times and original text remain traceable. This is consistent with [OpenAI Whisper’s confidence/silence handling](https://github.com/openai/whisper/blob/main/whisper/transcribe.py).

Reduction originally resolved some citations through already-filtered map outputs, dropping the original speech when a map fell back to an excerpt. It now resolves through the original drafts and still requires final independent source verification. Corrected source text also exposed a reservation collision: generation checkpoints included a source signature, while the billed request ID did not. Both now bind to the source; unchanged paid responses remain reusable, while different canonical text cannot reuse an incompatible chapter response or collide with a settled reservation. Unknown outcomes retain their conservative charge and replay guard.

Brief repair now submits the canonical speech as the evidence pool. The independent verifier receives bounded contextual windows for each claim and must return exact stored supporting text. A handful of model-selected representative citations no longer suppresses valid evidence elsewhere in the episode. This changes evidence retrieval, not the entailment standard or rights decision. Unresolved legacy chapter requests are also blocked before source-key migration can create a fresh billed request.

Live responses also exposed a concrete verifier-schema mismatch: a positive verdict could select a fragment shorter than the minimum evidence length, which the server correctly rejected. The response schema now offers only sufficiently long source segments. A previously completed positive-but-malformed selection gets one versioned, corrected-schema review; an unknown provider outcome cannot take that path. Focused brief generation bounds overview, themes and detail, and verifies the final output against canonical speech without redundant paid reviews of unpublished intermediate notes. Length-capped detail could end mid-sentence or mid-word; repair now retains completed sentences and preserves the raw response in its checkpoint. Existing complete prose remains unchanged. The final full suite covers these cases.

Deployment uses bounded server-side idle checks, including active feature repair and paid reservations. A busy-worker deferral preserves verified staging; archive/source hashes and executable checks are required before reuse. No active provider request was interrupted to obtain a deployment window.
